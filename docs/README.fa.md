# PS5 Update Blocker

نسخهٔ `0.1.0-experimental` برای آزمایش مسدودسازی ماندگار مسیر دانلود آپدیت سیستم PS5 است. هدف، فریمورهای جیلبریک‌شده‌ای است که SDK انتخاب‌شده می‌شناسد، تا نسخهٔ `13.60`.

**هنوز روی کنسول تست نشده است. ماندگاری بعد از ری‌استارت و جلوگیری واقعی از دانلود آپدیت سونی تأیید نشده است.** در معرفی این نسخه، عبارت «مسدودکنندهٔ دائمی و تضمینی» ننویسید.

## ساخت از صفحهٔ Actions گیتهاب

۱. مخزنی با نام دلخواه، مثلاً `ps5-update-blocker`، بسازید.

۲. فایل ZIP سورس را باز کنید و **محتویات پوشهٔ پروژه** را در ریشهٔ مخزن قرار دهید. پوشهٔ `.github` هم باید آپلود شود؛ مسیر فایل ساخت باید دقیقاً `.github/workflows/build.yml` باشد.

۳. شاخهٔ اصلی مخزن را باز کنید و به **Actions → Build PS5 payloads → Run workflow** بروید. اگر گیتهاب درخواست کرد، Actions را برای مخزن فعال کنید. با آپلود یا push فایل‌ها هم ساخت خودکار شروع می‌شود. برای نمایش دکمهٔ Run workflow، فایل workflow باید روی شاخهٔ پیش‌فرض باشد.

۴. اجرای سبزرنگ را باز کنید و از بخش **Artifacts**، فایل `ps5-update-blocker-experimental-...` را بگیرید.

۵. ZIP دانلودشده را باز کنید؛ داخل آن، بستهٔ `PS5-Update-Blocker-v0.1.0-experimental.zip` است. آن را هم باز کنید تا فایل‌های ELF در دسترس باشند.

نیازی به توکن شخصی، Secret یا آدرس کنسول نیست. این workflow فقط تست و کامپایل می‌کند و خروجی می‌دهد؛ Release عمومی نمی‌سازد و چیزی به کنسول نمی‌فرستد. Actions باید روی حساب و مخزن شما فعال و قابل استفاده باشد.

## فایل‌های خروجی

| فایل | کارکرد |
| --- | --- |
| `Status.elf` | وضعیت mount و مسیرهای آپدیت را می‌خواند. مسیرهای آپدیت را تغییر نمی‌دهد؛ گزارش را در `/data` ذخیره می‌کند. |
| `Disable-Updates.elf` | در دو مسیر مشخص آپدیت، پوشه‌هایی با فایل علامت‌گذار می‌سازد. اجرای دوباره، آن را به Enable تبدیل نمی‌کند. |
| `Enable-Updates.elf` | فقط پوشه‌های شناخته‌شدهٔ متعلق به همین پروژه را برمی‌دارد. آپدیتی دانلود یا نصب نمی‌کند و تنظیمات دانلود خودکار را روشن نمی‌کند. |

فایل‌های `SHA256SUMS.txt` و `build-info.json` مشخصات باینری‌ها و نسخهٔ SDK را ثبت می‌کنند. آرشیو سورس پروژه و SDK هم همراه خروجی است.

## روش این نسخه

پیلود در این دو مسیر پوشه می‌سازد:

```text
/update/PS5UPDATE.PUP
/update/PS5UPDATE.PUP.net.temp
```

داخل هر پوشه، فایل `.ps5-update-blocker-v1` با متن مشخص قرار می‌گیرد. هدف این است که دانلودر نتواند در همان محل فایل معمولی بسازد و یک پاک‌سازی ساده با `rmdir` هم پوشه را برندارد. این روش روی دیسک اثر می‌گذارد و به اجرای یک سرویس در پس‌زمینه وابسته نیست؛ اما هنوز نمی‌دانیم بوت، تعمیر حافظه یا دانلودر PS5 این پوشه‌ها را پاک یا دور می‌زند یا نه.

ماندگاری فایل روی دیسک با اثبات جلوگیری از آپدیت تفاوت دارد. این نسخه رفتاری برای جلوگیری از حذف بازگشتی یا پاک‌سازی یک سرویس برخوردار از دسترسی بالا ندارد. جلوگیری از آپدیت USB، دیسک یا Safe Mode هم در آن تأیید نشده است.

## اجرا با Payload Manager

فایل‌های ELF را مثلاً در پوشهٔ `pldmgr` روی USB قرار دهید و از Payload Manager ساختهٔ itsPLK وارد و اجرا کنید. ابتدا فقط `Status.elf` را اجرا کنید. یک ELF loader سازگار با دسترسی لازم باید فعال باشد؛ خود منیجر جای لودر و جیلبریک را نمی‌گیرد.

این ابزار باید **پیش از etaHEN یا HEN دیگری که `/update` را unmount می‌کند** اجرا شود. اگر پارتیشن از قبل unmount شده باشد، ابزار عملیات را رد می‌کند. در این حالت، دستگاه را دوباره راه‌اندازی و جیلبریک کنید و پیش از بارگذاری چنین HENی، با لودر مستقل و منیجر وضعیت را بررسی کنید. پیلود پارتیشن را خودکار mount نمی‌کند.

راهنمای مرحله‌به‌مرحله در [آزمایش روی کنسول](TESTING.fa.md) است. در طول تست ماندگاری، هیچ‌کدام از پیلودهای این پروژه را در autoload نگذارید؛ اجرای دوبارهٔ Disable بعد از هر بوت، نتیجهٔ تست ماندگاری را نامعتبر می‌کند.

## گزارش‌ها و خطاها

```text
/data/ps5-update-blocker/status.log
/data/ps5-update-blocker/disable.log
/data/ps5-update-blocker/enable.log
```

هر اجرا، گزارش قبلی همان عمل را جایگزین می‌کند. پیش از اجرای دوباره، گزارش مورد نیاز را با FTP ذخیره کنید. اگر نوشتن گزارش ممکن نباشد، خروجی فقط به stdout لودر می‌رود. شکست لودر یا SDK پیش از ورود به برنامه ممکن است اصلاً گزارش یا اعلان این پروژه را نسازد.

| کد | معنی |
| ---: | --- |
| `0` | عملیات یا بررسی کامل شده؛ متن وضعیت را بخوانید. |
| `1` | خطای خواندن، نوشتن یا همگام‌سازی؛ وضعیت نهایی را بررسی کنید. |
| `2` | فایل یا پوشهٔ ناشناخته حفظ شده است. |
| `3` | فقط بخشی از مانع وجود دارد یا نتیجهٔ نهایی مطابق انتظار نیست. |
| `4` | مسیر `/update` پارتیشن واقعی قابل استفاده نیست یا برای تغییر، فقط‌خواندنی است. |
| `5` | یک نمونهٔ دیگر از همین ابزار قفل عملیات را نگه داشته است. |
| `6` | نسخهٔ فریمور خارج از محدودهٔ هدف است یا تشخیص داده نشده است. |

`PLACEHOLDERS_PRESENT` فقط وجود دو پوشهٔ معتبر در لحظهٔ بررسی را تأیید می‌کند. `NO_OWNED_PLACEHOLDERS` هم به معنی نبودن مسدودکننده‌های دیگر نیست.

اگر فایل PUP واقعی، دانلود نیمه‌کاره، پوشهٔ خالی قدیمی، symlink، علامت‌گذار خراب یا فایل اضافه‌ای وجود داشته باشد، ابزار آن را پاک نمی‌کند. Enable هم ابتدا هر دو مسیر را بررسی می‌کند؛ وجود محتوای ناشناخته در یکی از آن‌ها باعث توقف می‌شود. پوشهٔ قدیمی متعلق به ابزار دیگری خودکار پذیرفته نمی‌شود.

قطع اجرا ممکن است یک پوشهٔ کامل باقی بگذارد؛ اجرای دوبارهٔ همان عمل می‌تواند ادامه دهد. قطع اجرا پیش از کامل‌شدن علامت‌گذار، محتوای مبهمی باقی می‌گذارد که باید دستی بررسی شود. از حذف بازگشتی کل `/update` استفاده نکنید. فایل خالی `.ps5-update-blocker.lock` بعد از Enable باقی می‌ماند و برای قفل عملیات همین ابزار است؛ سرویس سونی این قفل را رعایت نمی‌کند.
